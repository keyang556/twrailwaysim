## 助理

你這個修正是正確的，我前一版把**成功站的角色描述錯誤擴大了**，需要立即修改路線模型。

之前寫法：

> 海線 → 追分 → 成功 → 烏日 → 臺中

這是不正確的。

正確運轉邏輯應修改為：

# 修正：成功、追分、臺中地區路網

## 一、成功站定位

成功站主要是：

**臺中地區山線與海線轉接的重要節點**

不是：

海線列車必經站。

成功主要服務：

- 山線南下／北上列車進入臺中地區
- 臺中港線相關運轉需求
- 部分路線銜接

## 二、海線進入臺中方向

正確路線：

```text
彰化
 |
 |（海線）
 |
追分
 |
大肚
 |
龍井
 |
沙鹿
 |
清水
 |
大甲
```

（方向依列車行駛方向判斷）

重點：海線列車在**彰化～成功區間前的分歧位置**，經由道岔**倒插進追分方向**，而不是：

```text
海線 → 成功站
```

## 三、山線進入臺中區

山線方向：

```text
彰化
 |
大慶
 |
臺中
 |
太原
 |
潭子
 |
豐原
```

成功不作為山線進臺中的必經點。

## 四、資料架構修改

原本：

```text
成功
 |
追分
 |
臺中
```

刪除。

改為：

```text
海線

彰化
 |
海線區間
 |
追分方向分岔
 |
臺中地區

山線

彰化
 |
大慶
 |
臺中
```

## 五、AI調度修正

如果班次：

```text
路線 = 海線
目的地 = 臺中
```

允許：彰化 → 海線 → 追分方向 → 臺中地區  
禁止：彰化 → 成功 → 臺中

如果班次：

```text
路線 = 山線
```

允許：彰化 → 大慶 → 臺中  
禁止：經追分

# v1.5-14 路線模型修正：成功站／追分分歧

## 一、成功站位置與功能修正

成功站位於：

**彰化北側、臺中地區南端**

不是海線與彰化直接連接的必經點。

正確關係：

```text
                 山線
                  │
彰化 ───────── 大慶 ─ 臺中
                  │
                  │
               （臺中地區）
                  │
                成功
                  │
             海線聯絡線
                  │
                追分
                  │
                海線
```

（示意路網，實際以道岔進路資料建立）

## 二、海線往彰化方向

```text
海線
 ↓
追分
 ↓
彰化方向
```

不進入成功站。

錯誤：海線 → 成功 → 彰化  
正確：海線 → 追分 → 彰化方向

## 三、海線往臺中方向

```text
海線
 ↓
追分
 ↓
成功方向
 ↓
臺中地區
```

但不代表進成功站停靠；成功是聯絡線節點，不是一般經停站。

## 四、豐原／臺中往海線方向

```text
豐原
 ↓
臺中
 ↓
成功
 ↓
追分
 ↓
海線
```

不是：

```text
臺中
 ↓
彰化
 ↓
海線
```

## 五、AI路線判斷修正

海線 → 彰化：允許海線 → 追分 → 彰化方向；禁止海線 → 成功 → 彰化。

臺中 → 海線：允許臺中 → 成功方向 → 追分 → 海線；禁止臺中 → 彰化 → 海線。

山線列車，例如豐原 → 彰化：豐原 → 臺中 → 大慶 → 彰化，不經成功、追分、海線。

## 六、資料庫修改

```text
成功 = 臺中地區聯絡節點

功能：
- 臺中 ↔ 海線聯絡
- 非海線必經站
- 非彰化方向中轉站
```

```text
追分 = 海線與臺中聯絡線節點
```

```text
彰化 = 山線、海線匯合站
```

## 助理

收到，修正 AI 調度邏輯。

前一版提到「前方車站滿線等待」容易讓系統看起來像一般運轉狀態，這不符合正常台鐵運行。

正常情況下，列車依時刻表、進路排列、月台配置與閉塞狀態正常進站、停靠、發車，不會頻繁出現站外停等、無法進站或月台全滿。

站外等待改為特殊事件，只有臨時事故、大幅誤點造成調度衝突、災害模式、施工封鎖或臨時管制時觸發。

正常 AI 進路流程為取得時刻表、確認下一進路、檢查閉塞、檢查道岔、確認月台及允許進站。只有 `異常事件 = true` 才進入站外等待。

接著開始 **v1.6-3：ATP／列車保安系統基礎建立**。

加入每區間最高允許速度、曲線限制、進站限制及道岔限制。

號誌與速度連動：綠燈可依限制速度行駛；黃燈準備減速；紅燈禁止越過。

超速警告系統比較目前速度與允許速度，第一次超速播放警告音，持續超速時由後續完整 ATP 強制介入。

EMU3000 駕駛介面預留電門、制軔、緊急制軔、速度表及號誌顯示，保持 A 鍵制軔、D 鍵電門。

竹南必須選擇山線或海線方向；彰化加入山海線匯合及南北向進路；成功是山線車站且區間車停靠，追分是海線與臺中地區聯絡節點。

AI 調度依時刻表、列車位置及進路需求自動操作，但不能修改固定路線、任意改山海線或讓列車違反停靠規則。

異常事件介面預留道岔故障、號誌故障、列車故障及延誤處理，正常情況不觸發。
